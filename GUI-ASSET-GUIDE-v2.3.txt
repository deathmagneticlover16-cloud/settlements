SUGGESTED MASTER SIZES
- Small button source: 80x20 or 96x20
- Big button source: 160x24 or 192x24
- Dropdown row: 160x20
- Modifier/trait icon: 16x16 (optionally draw at 20-24 logical pixels)
- Header strip: make tileable or nine-slice friendly rather than one screen-width bitmap.
- Panels: preferably nine-slice style so one asset works at many screen sizes.

REUSABLE ASSETS
Use ONE small_button/big_button/dropdown family across all screens rather than drawing a unique button texture per page. Likewise, one positive/negative/mixed frame can surround different ItemStack/custom icons.

HOW TO WIRE YOUR ART IN JAVA
The screen classes are in:
src/main/java/ee/lastpagans/settlementprototype/client/

The current dark rectangles are calls similar to:
graphics.fill(left, top, left + W, top + H, ...)

Replace panel fills with blits from ResourceLocation textures. Keep all server actions/network packets unchanged. This means a visual redesign does not need to rewrite settlement logic.

Recommended pattern:
private static final ResourceLocation PANEL = new ResourceLocation("settlementprototype", "textures/gui/common/panel.png");
...
graphics.blit(PANEL, x, y, u, v, width, height, textureWidth, textureHeight);

For scalable boxes, either:
1. create a nine-slice helper (best), or
2. split art into corners/edges/center and tile/stretch only safe portions.
Do not stretch ornate borders blindly; they look bad at different GUI scales.

WHAT NOT TO CHANGE
Do not encode gameplay values into image names or screen coordinates. Keep traits/modifiers/settlement values data-driven and let the screen choose an icon. That way balance/code changes do not require redoing the GUI art.

GUI SCALE TARGET
The large campaign pages need substantial logical space. At 1920x1080, GUI scale 2-3 is the practical target for the current 2.3 layouts. A later pure-UI pass can make every page fully reflowable for extreme scale 4+ without changing the underlying data/network API.
